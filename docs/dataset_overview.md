# Dataset Overview

## Source
**NYC Taxi & Limousine Commission (TLC) — Yellow Taxi Trip Records**, plus the
companion **Taxi Zone Lookup** table.
<https://www.nyc.gov/site/tlc/about/tlc-trip-record-data.page>

The full records are published monthly as Parquet files. They are **not committed
to this repository** (see `data/external.txt`); a seeded synthetic sample with the
same schema is generated by `data/generate_sample.py` so the pipeline runs offline.

## Size & dimensions
| | Full TLC dataset | Committed sample |
|---|---|---|
| Rows | ~3–4M per monthly file; ~60M for 2024–mid-2025; ~1.5B (~50 GB) since 2009 | 40,000 trips |
| Columns (trips) | ~18–19 fields (a `cbd_congestion_fee` column was added for 2025+) | 13 core fields |
| Zone lookup | 265 zones × 4 columns | 35 zones × 4 columns |
| Format | Parquet (monthly files ~50 MB compressed) | CSV |

**Scope used here:** 1–3 monthly files (~3–9M rows) would be referenced
externally for full runs; the committed 40K-row sample is for offline,
one-command reproduction. Schema types drift slightly across years in the real
files (e.g. `passenger_count` as INT vs DOUBLE), which is why ingestion uses an
explicit schema rather than inference.

## Schema (trip records)
| Column | Type | Description |
|---|---|---|
| `VendorID` | int | Provider code (1, 2) |
| `tpep_pickup_datetime` | timestamp | Trip start |
| `tpep_dropoff_datetime` | timestamp | Trip end |
| `passenger_count` | int | Passengers |
| `trip_distance` | double | Miles |
| `PULocationID` | int | Pickup zone id (joins to lookup) |
| `DOLocationID` | int | Dropoff zone id |
| `payment_type` | int | 1 = card, 2 = cash |
| `fare_amount` | double | Metered fare (USD) |
| `tip_amount` | double | Tip (USD) |
| `tolls_amount` | double | Tolls (USD) |
| `improvement_surcharge` | double | Fixed surcharge (USD) |
| `total_amount` | double | Total charged (USD) |

**Zone lookup:** `LocationID` (int), `Borough`, `Zone`, `service_zone` (strings).

## Licensing
Public open data published by the City of New York (free to use). The committed
sample is synthetic and carries no third-party license.

## Preprocessing (ingestion stage)
1. Read the source (CSV sample **or** real TLC Parquet, auto-detected) and
   **normalize** it to the 13 canonical typed columns. CSV uses an explicit
   schema (no inference); Parquet is read with its native schema and projected
   onto the canonical columns, casting types (e.g. `passenger_count` DOUBLE →
   INT) and dropping the extra fee columns real files carry. Write Parquet.
2. Profile data quality: row count, null counts, invalid distance/fare counts.
   The sample intentionally contains ~2% dirty rows (zero distance, negative
   fare, zero duration) so cleaning in later stages is meaningful.

To validate on real data: `make download-real && make validate` (see
`docs/real_data_validation.md`).
